# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1: Read-Only Knowledge Layer.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> **Scope note:** Phase 1은 read-only. 5-key 승인 게이트, proposePatch/applyPatch UI는 Phase 2 경계 (D-12.3). 이 계약은 Phase 1 SSE 스트리밍 + 드리프트 배너 + 에러 배너만 다룬다.

## Design System

| Property | Value | Source |
|----------|-------|--------|
| Tool | none | stack lock: htmx + vanilla CSS (React/Next/Vite 아님 — shadcn gate 해당 없음) |
| Preset | not applicable | shadcn 미초기화 |

**Style Direction: Terminal/Swiss-International (다크)**

근거: Phase 1의 핵심 출력물은 (1) LLM 텍스트 스트림, (2) 모노스페이스 셸 명령 (`fix` 필드 verbatim), (3) 도구 호출 진행 상태이다. 다크 배경은 "default minimal"이 아니라 *운영자 콘솔 컨텍스트의 의도적 선택*이다 — 서버룸/홈랩 환경에서 저조도 사용, 쉘 명령이 배경과 대비되어야 함, 에러 배너가 빨간색으로 눈에 띄어야 함. 밝은 배경에서는 에러 빨간 배너가 오히려 덜 두드러진다. (web/design-quality.md: "Do not default to dark mode automatically" — 여기서는 자동 기본값이 아닌 명시적 선택이다.)

## Element Inventory & SSE Wiring

Phase 1의 `public/index.html` DOM 계약. 이 테이블이 executor의 구조적 근거다.

### Drift 배너 배치 결정 (D-13.4 vs UI-04 reconcile)

D-13.4: "drift 감지 시 SSE `text-delta` 첫 chunk로 warning banner 텍스트 prepend"
UI-04: "services.yaml drift warning이 UI header에 표시됨"
D-15.2: error 배너는 `#error-banner` 별도 div

**결론:** `#drift-banner`는 독립 div (UI header 영역, 항상 출력 영역 위). D-13.4의 "prepend" = *서버가 첫 SSE text-delta 전에 drift 정보를 별도 SSE 이벤트로 전송해 배너를 채운다*는 의미. "text-delta 첫 청크에 텍스트로 믹스"가 아니다. 에러 배너(`#error-banner`)와 드리프트 배너(`#drift-banner`)는 각각 독립 dom 영역.

### DOM 구조

```
body
├── #drift-banner        (KB-03 staleness warning — header 영역)
├── #error-banner        (D-15.2 에러 envelope 표시)
├── #output              (LLM text-delta 스트림)
│   └── .tool-event      (tool-start/tool-result 인라인 카드)
├── #status-bar          (final 이벤트 완료 표시)
└── form                 (prompt 입력)
    ├── input#prompt
    └── button[type=submit]
```

### SSE 이벤트 → DOM 매핑

| SSE Event | DOM Target | sse-swap | hx-swap | 표시 내용 | 기본 상태 |
|-----------|------------|----------|---------|-----------|----------|
| `text-delta` | `#output` | `text-delta` | `beforeend` | LLM 텍스트 청크 연속 추가 | 비어있음 |
| `tool-start` | `#output` | `tool-start` | `beforeend` | `.tool-event` 카드: `· listContainers 호출 중...` (accent 색상 점) | — |
| `tool-result` | `#output` | `tool-result` | `beforeend` | `.tool-event` 카드: `✓ listContainers — 컨테이너 12개` 또는 `✗ listContainers — 실패` | — |
| `final` | `#status-bar` | `final` | `innerHTML` | `✓ 완료` (accent 색상) — 1.5초 후 fade | 숨김 |
| `error` | `#error-banner` | `error` | `innerHTML` | 에러 배너 HTML (빨간 배경 + monospace fix 필드) | 숨김 (`display:none`) |
| drift (custom) | `#drift-banner` | `drift` | `innerHTML` | `⚠ services.yaml 불일치: docker-only 서비스 2개 발견` | 숨김 (`display:none`) |

**Note:** drift 이벤트는 `event:drift`라는 별도 SSE 이름으로 서버가 전송. `text-delta` 스트림에 믹스되지 않음. 서버가 KB-03 staleness detection 결과에 따라 선택적으로 전송.

### `#drift-banner` 상세

```
표시 조건: event:drift 수신 시 display:block
배경: var(--color-surface)
테두리: 2px solid #f59e0b (amber-500 — 경고 전용 1회성 색상)
텍스트: var(--font-size-heading) + var(--font-weight-semibold)
위치: 페이지 상단 고정 (position: sticky top: 0)
닫기: 없음 (운영자가 인지하고 조치할 때까지 유지)
```

### `#error-banner` 상세

```
표시 조건: event:error 수신 시 display:block
배경: var(--color-error) + 10% 투명도 오버레이 (#ef444418)
테두리: 1px solid var(--color-error)
헤더: problem + cause — font-family-sans, font-weight-semibold
fix 필드: font-family-mono, color: var(--color-mono) → 에러 배너 내에서는 #fca5a5 (red-300)
         "복사" 버튼 없음 Phase 1 (텍스트 선택으로 복사)
```

### 입력 폼

```
단일 input#prompt: width 100%, 내부 패딩 var(--space-sm), monospace font
자동완성: autocomplete="off"
자동포커스: autofocus
placeholder: "질문하세요. 예: ais-prod redis 어디 쓰여?"  (한국어)
submit button: "전송" 텍스트, accent 색상 테두리
```

## Interaction Contract

Phase 1 상호작용 규칙.

### 입력 → SSE 연결 흐름

1. 운영자가 `input#prompt`에 질문 입력 후 Enter 또는 `전송` 클릭
2. htmx `hx-post="/chat"` → 폼 전송
3. SSE 스트림 연결: `#output` div의 `sse-connect` 속성이 `/chat-stream`에 연결
4. 서버가 drift 배너 필요 시 `event:drift` 먼저 전송 → `#drift-banner` 표시
5. `event:text-delta` 순차 수신 → `#output`에 `beforeend`로 추가
6. `event:tool-start` 수신 → `.tool-event` 카드 `#output`에 추가
7. `event:tool-result` 수신 → 해당 tool-start 카드 업데이트 (동일 위치)
8. `event:final` 수신 → `#status-bar`에 `✓ 완료` 표시, 1.5초 후 fade
9. `event:error` 수신 → `#error-banner` 표시 (스트림 계속되거나 종료)

### SSE 재연결 주의사항 (PITFALL #4)

htmx-ext-sse는 `EventSource` 기반으로 자동 재연결한다. LOOP-07 idempotency token으로 중복 Claude API call을 서버에서 방지한다. UI 계약: 재연결 시 `#output` 내용은 초기화하지 않음 (누적 유지).

### 오류 상태 전환

- `event:error` 수신: `#error-banner` display:block (기존 내용 교체). `#output` 스트림은 중단.
- `retryable: false` 에러: `input#prompt`를 비활성화하지 않음 — 운영자가 다른 질문 가능.
- `retryable: true` 에러: Claude가 한국어로 재시도 안내 텍스트를 `#output`에 text-delta로 전송.
